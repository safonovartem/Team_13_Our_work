# Team_13_Our_work
Репозитории с кодом программы для расчёта ограждений для резеуаров, которую мы реализуем в рамках программы "Лаборатория ИИ рещений"

# Правила работы над проектом 
## Структура
**main** - Основная версия проекта. Сюда попадает только проверенный код.

**Рабочие ветки - конкретные задачи (Пример)**

feature/frontend-auth

feature/backend-calculations

feature/ai-interpolation

fix/backend-database

| Тип ветки   | Назначение                                  | Пример                      |
| ----------- | ------------------------------------------- | --------------------------- |
| `main`      | Основная стабильная версия                  | `main`                      |
| `feature/`  | Новая функциональность                      | `feature/report-generation` |
| `fix/`      | Исправление ошибок                          | `fix/calculation-error`     |
| `refactor/` | Изменение структуры без изменения поведения | `refactor/api-services`     |
| `docs/`     | Документация                                | `docs/setup-guide`          |

### Пример работы
1. **Разработчик получает задачу**
    
    Например: реализовать сохранение расчётов в SQLite.
    
2. **Создаёт новую ветку от main**
    
    `feature/save-calculations`
    
3. **Пишет код и сохраняет изменения**
    
    Делает осмысленные коммиты по мере работы.
    
4. **Отправляет ветку на GitHub**
    
    `git push origin feature/save-calculations`
    
5. **Создаёт Pull Request (PR)**
    
    Запрашивает проверку другого участника.
    
6. **Проходит проверку и тесты**

7. 8. **Изменения объединяются с main**
    
    Через кнопку Merge на GitHub.

## Code Review 
Кто кого проверяет перед pull-request

|Автор изменений|Кто проверяет|
|---|---|
|Frontend-разработчик|Один из Backend-разработчиков или другой назначенный участник|
|Backend-разработчик №1|Backend-разработчик №2|
|Backend-разработчик №2|Backend-разработчик №1|
|AI-разработчик|Backend-разработчик, знакомый с интеграцией и математической частью|
    
    Если обнаружены проблемы — исправляет их.
    
## Тесты
### Backend

| Что проверяем      | Пример                                                         |
| ------------------ | -------------------------------------------------------------- |
| Основные функции   | Корректность выполнения расчёта                                |
| Валидация данных   | Что будет при отсутствии обязательного параметра               |
| Ошибочные значения | Что будет при отрицательном объёме или некорректном расстоянии |
| Работа с БД        | Сохранение и получение расчёта                                 |
| API                | Корректность ответов FastAPI                                   |

### Frontend
- TypeScript — проверка типов.
    
- ESLint — проверка распространённых проблем в коде.
    
- Vitest — тестирование отдельных функций и компонентов.
    
- React Testing Library — при необходимости тестирование взаимодействия с интерфейсом.


## Сборка
Можно использовать GitHub Actions там достаточно прописать YAMI файл - он автоматически запускает проверки после отправки изменений на GitHub или создания Pull Request.
